# Errors — product statements

¶¶ The product-level stances every failure answers to, kept alike across a scope's loads, a source, the data primitives and the server render: the one shape a failure takes, how it is classified, and what a classification means. What a slot does with a failure is the Island area's; what status a failure earns is the Server rendering area's.

¶¶ A statement binds from its approval token alone (jnana-kit:///plugin/docs/product.md §Lifecycle); a proposed one binds nothing until the user walks it.

## One shape

- ⭑ERR-1 A failure anywhere reaches its reader in one shape, so one handling serves an error slot, an in-content badge and a server status alike. {proposed}
- ⭑ERR-2 A failure carries two readings: what kind it was, and whether trying again can help. {proposed}
- ⭑ERR-3 The kinds of failure are an open vocabulary an app extends. {proposed}
- ⭑ERR-4 An unclassified failure reads as failed, with no claim about trying again. {proposed}
- ⭑ERR-5 Any error an app already throws can carry a classification; no error class of rati's is required. {proposed}
- ⭑ERR-6 A classified failure keeps its classification across the wire from the server to the client. {proposed}

## Who classifies

- ⭑ERR-7 A failure is classified where the app turns a response into an error; rati never reads a response. {proposed}
- ⭑ERR-8 A thing that does not exist is an answer, never a fault: it reaches the error slot as not available and is never retried. {proposed}
